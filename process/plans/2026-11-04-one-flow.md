# Plan: one flow, A OR B, a screen rail, one toolbar

This is the brief for one Claude Code session that rebuilds the UX Woz front end around a single
flow and cuts what that makes obsolete. It does not change the model calls, the frame page or the
providers, apart from one line in the prompt.

Start by reading `AGENTS.md`, then the latest file in `process/journal/` (it describes the stacks
this plan removes). We are in an early MVP: iteration speed wins. Delete freely. Rewrite a file
when that is shorter than patching it. Keep no compatibility except the cache migration below.

## Why

Stacks of variants, tabs, Compare, lines fanning down left and right, and a floating tree confuse
people. The new model is that **only screens the user picked exist**. A new screen shows two
designs side by side; the user clicks one, and the other is gone. After that, the user changes a
screen by asking for an edit.

## Example

1. The user types *a cat litter box app* and clicks Generate. The canvas zooms to fit two screens
   side by side, with a large **OR** between them. Above each screen is one sentence naming its
   idea: *Status cards first, actions below* and *One big clean button on top*. Both stream in,
   and neither is clickable inside.
2. The user clicks anywhere on the right one. It becomes *L1 Home*, the zoom goes back to what it
   was before, and the left one is deleted.
3. The user clicks *Camera* inside L1. The new screen's A OR B appears below L1, in L2's place.
   The user picks one.
4. The user clicks ✎ in the rail to the right of L2. A drawer opens at the window's right edge.
   The user types *show one level indicator, not four* and clicks Make the change. L2 updates in
   place, and **↶ Undo** brings the old version back.
5. Back in L1, the user clicks *Settings*. Its A OR B appears in a new column beside the Camera
   branch, still at level 2. Fit all shows the whole tree, like a Figma page.

## Decisions already made (by the user)

- Every new screen (the first one and every click to a new screen) comes as A OR B.
- **Edit** makes one new version in place; **Undo** restores the previous version.
- **Regenerate** makes one new design in place, from the screen's prompt; Undo works for it too.
- Edit and Info open in a **docked right drawer**. The canvas narrows and pans so the screen
  stays fully visible beside the drawer.
- All screens stay on the canvas as a tree. Nothing is hidden when the user branches.

## Decisions made here (change them if they feel wrong)

- **Parallel, random side.** The two designs are made at the same time, as today. The "clearly
  different alternative" request goes to a random side (A or B), so position carries no bias.
- **The idea sentence.** The model starts its reply with `<title>Name</title>` and then
  `<meta name="idea" content="...">`: one short sentence naming the design idea (*Common actions
  as buttons on top*). Show the idea above each A/B screen, and under the name everywhere else.
- **Previews are live but locked.** A/B frames stream as today and run their script at the end,
  so charts draw. A transparent layer over each frame takes the click. A side can be picked once
  it has finished. A failed side shows its error; if both fail, the slot goes away.
- **Picking.** A pick keeps that design as the screen's first version and deletes the other. If
  the other one is still streaming, the server drops it when it finishes. A reload while a choice
  is open shows the same A OR B again, at no cost.
- **Zoom.** Before an A OR B shows, remember the zoom and scroll, then fit both designs. After the
  pick, restore the zoom and pan the picked screen into view.
- **Names.** Screens keep a level (it gives the row) and lose letters: *L2 Camera*.
- **Lines.** Draw one thin line from a parent to each child it made: straight down in the same
  column, an elbow for a branch. Links back to existing screens get no line.
- **Current screen.** The screen the user last picked, clicked in, or chose in Nav. It has the
  rail at full strength; other screens show their rail on hover. Fit screen uses it.
- **Dropped.** "Start over from an edited prompt" (Edit covers it), Compare, tabs, the slide, the
  floating tree, letters, the metrics line under the header (cost and timing move into Info and
  into a small status pill at the bottom of the canvas).

## Data and API

The cache stores one screen per key, with versions instead of variants:

```
CacheEntry { key, app, action, level, parent: {key, label} | null,
             versions: Version[]        // the last one shows; Undo removes it
             proposals?: Version[] }    // the open A OR B, until a pick
Version = today's Candidate minus letter, deleted, alternative, replaces, editOf
          plus idea; feedback stays (the Edit request that made it)
Link { from, to, label, createdAt }     // no variant index
```

- **Migration** on load: each old entry keeps only its picked candidate as `versions[0]`. Links
  from other variants go, and so do screens that no picked screen reaches any more. If this gets
  hairy, start a new cache file instead, keep the old one on disk, and tell the user.
- `POST /api/screen {app, action?, model?, device?, from?, label?}`: a new screen. Two proposals
  stream as variants 0 and 1, and `done` stores them. A cache hit on a screen with open proposals
  sends them again.
- `POST /api/pick {key, index}`: keep that proposal and drop the other.
- `POST /api/revise {key, change?}`: one new version. A `change` makes an Edit (the model gets the
  current HTML), and no `change` regenerates from the screen's prompt. It streams like a screen.
- `POST /api/undo {key}`: drop the newest version (404 when only one is left).
- `POST /api/delete {key}`: delete a screen and the screens only it reaches. The first screen
  takes the mockup with it.
- `/api/map`, `/api/apps`, `/api/link {from, to, label}`, `/api/delete-app`, `/api/warmup` and
  `/api/config` stay. Remove `regenerate`, `replace`, `variant`, `edit: {variant, …}` and
  `/api/choose`.

## Front end

**Canvas** (new `canvas.ts`, replaces `feed.ts`). It is one panning and zooming surface on the dot
grid, as today. A tidy tree layout puts one row per level; each row is as tall as its tallest
screen, and each subtree is as wide as its screens. Screens sit at absolute positions. Reuse the
frame creation, height messages, the 300 ms streaming rebuild and the zoom math from `feed.ts`.

**Rail.** A column of large icon buttons right of each screen, kept at about 40 px on screen
whatever the zoom: ✎ Edit, ↻ Regenerate, ↶ Undo (only with 2+ versions), ⓘ Info, ✕ Delete. The
two simple actions run at once (Delete asks first). Edit and Info open the drawer.

**Drawer.** A 360 px panel at the right edge, with two tabs: Edit (textarea *What should change?*,
Make the change, and the list of past changes) and Info (today's fields plus the idea). The
canvas gets narrower and pans the current screen into view. Esc closes the drawer.

**Toolbar.** One bar about 44 px tall, with three parts:

- **Left, project menu**: a button with the mockup's prompt, cut short, opening a dropdown:
  - *New mockup*: opens the generate panel. It has a growing multi-line prompt, Generate, Model,
    Device and Theme (their values stay per browser, as now).
  - *Templates*: today's Try examples.
  - *Recent mockups*: today's History list.
  - Start over and Delete as icons, both asking first.
  With no mockup open, the generate panel sits large in the middle of the canvas.
- **Middle, Nav**: a button naming the current screen (*L2 Camera ▾*). Its dropdown lists every
  screen as an indented tree, with the current path marked; choosing one makes it current and
  pans to it. It replaces `tree.ts`.
- **Right, zoom**: `[−] [100% ▾] [+] [⤢ fit screen]`. The dropdown holds everything, with key
  hints like Figma: Zoom in ⌘+, Zoom out ⌘−, 50 / 100 / 200 %, Fit all ⇧1, Fit screen ⇧2, Fit
  screen width ⇧3. Under about 900 px wide, only the dropdown stays.

## Delete

- `tree.ts`, and from `feed.ts` everything about stacks, tabs, Compare, the slide, edges, back
  cards and variant lines (most of the file).
- From `app.ts`: rows following the pick, first-to-show-in-front, per-variant pick logic.
- From `cache.ts` and `keys.ts`: letters and per-level letter counters, `letterAt`,
  `letterIndex`, `variantId`, `choose`, `replace`, `deleteVariant`, and `variant` on links and
  parents.
- From `shell.css` and `index.html`: header rows, pickers, examples, the zoom slider, stack styles.
- Tests that cover these. Write small new ones for the new cache, pick, undo, revise and
  migration.
