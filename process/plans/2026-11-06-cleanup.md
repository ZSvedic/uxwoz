# Cleanup: what the paper canvas removes

This list names everything the build deletes before it adds the boxes: step 2 of
[the paper canvas plan](2026-11-06-paper-canvas.md). It owns the removal and the check that it
happened. It adds no feature.

## Example

`src/packages/core/src/spec.ts` has 566 lines today. After the cleanup the file is gone. Two of
its functions serve any screen, `firstCopy` and `cutProse`, and they move to `generate.ts`. The
five test files written for it go with it.

## Why a step of its own

The spec feature took the app's code from 160 KB to 249 KB and its tests from 50 KB to 125 KB.
A build that adds the boxes beside it would carry both. So the removal comes first, in commits
that only delete, and the new code starts from the smaller base.

## What goes

Delete it. Leave no commented-out code, no flag and no code that reads the old spec.

Core (`src/packages/core/src/`):

- `spec.ts`, except `firstCopy` and `cutProse`. `plan.ts`. `review.ts` (step 4 writes the fixer new).
- `tree.ts`: planned screens taken from the spec's flow and tabs. The tree keeps links.
- `cache.ts`: `specs`, `reviews`, suggestions and deleted rows. A file of format 4 loads with
  both dropped; the dev cache is backed up first.
- `frame.ts`: the redraw of tabs and Back by message, the styles for `data-ui="tabs"` and
  `data-ui="back"`, the `data-tab` mark.
- `generate.ts`: a design's spec lines and the check. `prompt.ts`: the `spec` and `flow` parts of
  a request and the spec sentence of `EDIT_REQUEST`.

Web (`src/packages/web/`):

- `server.ts`: `/api/spec/drop`, `set`, `remove` and `suggestion`, the plan before the first
  screen, the review pass, and the spec fields in `/api/map`, `/api/pick` and `/api/revise`.
- `app.ts`: the spec panel with its Export, the Spec button, the lines under a design, an Edit's
  lines in the drawer, the wait for a review.
- `canvas.ts`, `shell.css`, `index.html`: the markup and styles of those.
- `themes/mockup.css`: the `nav[data-ui="tabs"]` rules.

Prompts and docs:

- `spec/prompt-plan.md` and `spec/prompt-review.md`.
- `spec/prompt-screen.md` and its copy in `prompt.ts`: spec lines, the fixed markup for tabs,
  Back and switches, "1 or 2 new kinds of screen", "the details of two items are two screens".
  The prompt changes, so the cassettes are recorded again.
- Every spec paragraph in `spec/behavior.md`, `spec/code-contract.md`, `spec/ui-generation.md`,
  `README.md` and the code map of `AGENTS.md`.

Tests and scripts:

- `spec.test.ts`, `spec-review.test.ts`, `spec-review-3.test.ts`, `spec-review-5.test.ts`,
  `spec-panel.test.ts`, `review.test.ts`, `chrome.test.ts` and `cassettes/review.json`.
- The spec cases in the cache, server, races, frame, tree and cut-off tests.
- `scripts/spec-reading-test.ts` and `scripts/planner-test.ts`. Their reports stay in the journal.

## What stays

These came with the spec work and serve any app: the fixed device size, keeping the first copy
of a doubled reply, refusing a cut-off reply, versions and Undo.

## The check

The step is done when all of these hold.

- This search finds nothing:
  `grep -rniE "ui\.nav|ui\.back|core-flow|drawChrome|data-ui|specRequest|/api/spec" src spec README.md AGENTS.md`
- App code (`packages/core/src` and `packages/web/src`) is at most 175 KB, and tests at most 60 KB.
- `bun test` and `bun run typecheck` pass, and the app still makes, picks, edits and undoes screens.
- A critic reads the diff for leftovers: unused exports, unused styles, stale doc lines.

The finished version stays under 220 KB of app code. Each later step's report gives the size
before and after.
