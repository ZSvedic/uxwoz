# 2026-10-23: first MVP

The first working UX Woz: a prompt makes a screen, clicks make more screens, and every screen is
cached. This entry records what was built in about an hour, the choices made on the way, and what
was left out.

## What works

- A prompt streams the first screen into a sandboxed iframe with Pico inlined, rebuilt at most
  every 300 ms, exactly as [spec/ui-generation.md](../../spec/ui-generation.md) says.
- Buttons and links open the next screen. The iframe posts the action prompt to the app.
- Screens are cached on the server by normalized prompt; revisits take about 10 ms and cost nothing.
  Regenerate adds a version; only **Use this version** changes what revisits show.
- Model picker (Haiku default, Luna fast, Sol Ultrafast) and theme picker (Pico, hand-drawn sketch).
- Time to first visible screen, time to interactive, and cost per screen. With a warm Haiku the
  first visible screen came at about 0.8 s and the full screen at about 6 s.
- 16 bun tests, replaying two cassettes; no network calls.

## Choices

- **Action prompts as `data-action` attributes.** The brief describes three parts per screen (HTML,
  JS, action prompts). Putting the prompt on the control keeps the spec's "one fragment ending in
  one script" format, needs no extra parsing, and a control's prompt arrives with the control. Our
  own script in the frame turns the click into `postMessage`.
- **Cache key = product prompt + action prompt, no parent screen.** Two paths to the same action
  share one screen, which the brief leaves open. The model is part of the candidate, not the key, so
  switching models does not hide cached screens.
- **No runtime dependencies.** `Bun.serve` with an HTML import bundles the TypeScript page.
- **Prompt copy in code, checked against `spec/prompt-screen.md`** by a test, so `src/` runs without
  reading `spec/`.

## Cut

- Text feedback on a screen, "Generate 3 variants", and export for a coding agent (brief steps 3-4).
- Splitting HTML, JS and action prompts into separately streamed parts.
- Form values in action prompts (a submitted form opens the same next screen whatever was typed).
- Cucumber `.feature` files; tests are plain `bun test`.
- Calling Anthropic directly; Haiku goes through OpenRouter as measured.
