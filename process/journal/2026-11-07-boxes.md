# 2026-11-07: the boxes in the app

Build step 3 of [the paper canvas plan](../plans/2026-11-06-paper-canvas.md): Components, Rules
and Data on the canvas, paste by ID, the current link, and filing after each decision. It works on
NiceSnore: filing filled the boxes in 1 to 5 s for $0.001 to $0.004 a decision, and a component
edit redrew all six screens that paste it. App code went from 162.5 to 214.8 KB, under the 220 KB limit and over
the 200 KB aim.

## What was built

1. **The prompt.** The system prompt is the manual verbatim, then how to reply: HTML for every job
   but filing, links by `@id`, the paste markup, and the filing lines the paper test settled. The
   user message is the paper (app, device, titles, `id -> id` lines, the three boxes in full), then
   Draw, Edit or File. A test fails when the manual file no longer opens the prompt verbatim.
2. **Storage**, cache format 5: per mockup Rules, Data, the IDs each box used and deleted, and the
   last filing. A format 4 file loads with empty boxes and drops the spec feature's fields; checked
   on copies of the three dev caches (46, 7 and 6 entries). Backups: `temp/*.before-boxes`.
3. **Paste by ID and the current link** in `frame.ts`: `pasteComponents` and `markCurrent`, applied
   when a screen is shown, never stored. `tree.ts` reads links after pasting, so a tab bar's links
   still make the tree.
4. **Filing** in `filing.ts`: number the parts, ask Terra, parse the lines, apply them with
   refusals. The server files after a pick or a screen's Edit, one filing per mockup at a time; a
   click or a revise waits for it at most 5 s; `/api/map?wait=1` answers once it is done, and the
   page asks for it after each pick or Edit.
5. **The canvas**: a column of three labelled boxes left of the first screen, at the canvas's
   scale; component cards like screens; rules and table cells edited in place; three toolbar
   buttons with a count of new entries; Export as markdown in the project menu. Room is left for
   a fourth box (the column takes any number of sections).

## Decisions

- **A component is a cache entry of its own kind** (`kind: 'component'`, key `app » #id`), so Edit,
  versions, Undo, Info, Delete, the card, its rail and the drawer are the screen's own code. Tree,
  names, Nav and the screen count skip it. The cost is a filter in six places.
- **Filing writes the placeholder into the newest version in place**, with no new version: the
  screen looks the same, so a version would only fill Past changes. It does so only when the
  screen's HTML is still the one filed; otherwise the component still goes in the box.
- **`by` is who last wrote an entry**, not who first added it: a rule the user edits is the user's,
  which the fixer must leave alone.
- **New marks clear three seconds after a look** through a toolbar button, so the user sees them.
- **Only `data-action="back"` goes back.** The old guess from labels (*Back to cats*, *🏠 Home*,
  arrows) was code that knew what a Back button is.
- **A component's Edit is not filed**; a screen's Edit and every pick are.
- **An ID not in the box leaves its element as it is**, and paste goes three levels deep. A deleted
  component's empty placeholder still shows nothing; a model's hand-drawn part under an unknown ID
  stays visible.
- **The page polls once per decision**: `/api/map?wait=1`, guarded by a count of local changes, and
  asked again (without waiting) when a change or a stream crossed it.

## For step 4, the fixer

- **Join the filing chain.** `server.ts` runs one filing per mockup at a time (`filings`); a fixer's
  visit should take its turn in the same chain, so two writers never change the boxes at once.
- **Leave alone what the user wrote**: every entry has `by` (who last wrote it) and `at`.
  Components are entries with `kind: 'component'`; their versions carry `feedback` for an Edit.
- **A redraw is an Edit**: `reviseEvents` in `server.ts` with the fixer's sentence as the change
  gives a version and an Undo. It also starts a filing; the fixer may want to skip that.
- **The notes box**: `createSide()` in `boxes.ts` builds the column from a list of sections, and
  `Boxes` takes a new field; the toolbar's `[data-box]` buttons count new entries generically.
- **The prompt holds two reply forms now.** Haiku once answered an Edit with a filing line; the
  format now says which job gets which. A third form (the fixer's) should say so as plainly.
- **Mistakes the fixer will meet**: a screen that pastes a component that does not exist yet;
  `tab-bar` drawn with `position: fixed`; parts drawn by hand on screens made before their
  component (filing only takes a part from the screen decided on).
- **Room**: 5 KB left under 220, so step 4 starts by cutting. Candidates to cut first: `firstCopy` and `cutProse` in
  `generate.ts` (about 2 KB, and a guard for one model's failure, against the principle), the
  format 2 migration and plain-prompt links from before names (about 3 KB).
