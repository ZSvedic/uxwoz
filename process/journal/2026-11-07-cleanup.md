## Decisions

- **Cache format stays 4.** The entries have the same shape as before; a format-4 file loads, its
  `specs` and `reviews` are not read, and the next save drops them. A bump would only make the
  spec-era app refuse the new file. Step 3 bumps it when the boxes add a shape. Checked on copies of
  both dev caches: 46 and 6 screens load, saved as `{version, entries}`. Backups:
  `temp/screen-cache.json.before-cleanup` and `temp/screen-cache-spec.json.before-cleanup`.
- **The map-race guard in `app.ts` went too.** It kept a map fetched during a POST from overwriting
  newer changes, and was written for the review's polling. Now the map loads only after a failed pick.
- **"At least 3 controls with data-action" was not brought back.** The floor replaced it, and the
  list deletes the floor. Bringing back the older rule would be a prompt change of its own.
- Each commit passes `bun test` and `bun run typecheck`, so the order is tests, web, core, prompts,
  docs. That cost one extra recording of the server cassette (step 2).
