# 2026-11-07: the remakes

Build step 5 of [the paper canvas plan](../plans/2026-11-06-paper-canvas.md): make the fixer tidy
the boxes as well as it redraws screens, then remake three apps and score the version. Two sentences
in the manual's fixer section took the fixer on a planted NiceSnore from 9 to 23 of 25 repairs. The
remakes pass on readable boxes, first-screen time and code size, and miss on components pasted
(7 in 10). The 10-plant visit did not run: the OpenAI account ran out of credits. Everything that
changes a recorded call waits on the branch `paper-fixer-wording` for one `bun run test:record`;
`main` stays green.

## What was built

On `main`: the two scripts (4, 5) and a 0.5 KB comment cut in `app.ts`. On the branch
`paper-fixer-wording` (one commit, cut from `main`): 1 to 3 and the critic's fixes, with tests and
spec updates. It needs `bun run test:record`: the prompt bytes and the filed Data change, so 17
tests replay stale cassettes until then.

1. **The manual's fixer section**, in its three copies (the manual, `spec/prompt-screen.md`,
   `core/src/prompt.ts`). The first bullet now tells the fixer to go through the boxes entry by
   entry; a fact two screens show differently gets a redraw, not a rule:

   ```
   - Go through the boxes entry by entry. Ask of each: do two or more screens need it? If one screen
     or none does, remove it, even if a screen could use it. Merge entries that say one thing twice,
     keeping the older ID. Of two rules that disagree, remove the older one.
   - Add what filing missed: a part drawn by hand on three screens. Where two screens show one fact
     differently, redraw the older screen to match the newer one.
   ```

2. **A row belongs to the table above it.** Terra named each row by its own ID (`row nose-strips:
   …`), code refused every row, and the first NiceSnore's two tables had 0 rows. Now a row line
   joins the table directly above it, unless it names another table in Data.
3. **Code numbers the parts alone.** Haiku and Luna wrote `data-part` on their own screens (in 15
   versions of 8 screens, from the first draw), copying the prompt's example; code then added a
   second number, and one visit spent a redraw on *give every part a single unique data-part
   number*. `numberParts` drops a model's numbers first.
4. **`scripts/fixer-wording.ts`**: one wording of the section, 5 visits on each of two planted
   papers (the step 4 NiceSnore with its 5 plants, the paper test's held-out dashboard with 10),
   scored by code; `REAL=<cache>` adds a remake to count the rules a visit adds.
5. **`scripts/remake-plant.ts`**: the answer key for 10 plants on a copy of the NiceSnore remake
   (`temp/fixer-wording/nicesnore-remake-planted.json`), plus a rule by the user that must stay.

## Decisions

- **The scripts drive the server, not the mouse.** 45 screens by pixel clicks in the pane would
  have taken hours; the script makes the page's own calls, and I chose every pick and click.
  Screenshots and the box views come from the app.
- **The row fix and the parts fix are code, not manual.** Both are one reading of a reply form
  (a row's ID adds nothing after its table line; the app's numbers are the only numbers), not a
  guard against one app. I restarted NiceSnore after the row fix so all three ran the same code.
- **Wording 4 went in mid-remake**, measured first by Part A's method on a copy of the dashboard.
  The game's visits ran on it; its first visits added no number rules.
- **The critic's fixes came after the remakes**, so no remake ran them, and none was measured.
- **The NiceSnore plants are not held out**: three of the new sentences answer them almost word for
  word. The dashboard paper is the held-out score, 50 of 50 on wordings 1, 2 and 4.

## Where a simpler sentence would help

Not measured, so not in the manual:

- *A row belongs to the table above it* could be the form itself: `row: value | value | ...`.
- The fixer treats a mockup like an app (*make recording work*). A sentence for the Redraw bullet:
  *A mockup only shows: a button leads to the screen that comes next.*
- The fixer pointed *next level* at a new `level-shared`: *A screen drawn for one example item is
  the screen for every item; link to it.*
- Filing made the game's star bar a rule: *A part that shows on every screen is a component, even
  when its number changes.* That contradicts the manual's *a part whose content changes per screen
  stays a rule*, so it needs a test first.

## The critic's findings

One critic read the diff. Its two questions first:

- **One kind of app, one failure?** No: the two sentences, the row reading and the parts numbering
  are general. It noted that the wording was written against the NiceSnore plants: *reported*, the
  dashboard is the held-out score.
- **Not visible on the canvas?** No: every removal and redraw has a note and an Undo, a row filed
  into the wrong table shows in Data.

Then, fixed with tests unless said:

1. From the second visit on the fixer reads only new screens, so *do two or more screens need it*
   could remove a used `tab-bar`: each component in the paper now lists the screens that paste it
   (*pasted on: home, nights*). Rules and tables get no such list. *Left*: no second-visit plant
   test.
2. A row naming another table in Data went into the table above: now refused.
3. *Older* and *newer* had nothing to go by: a visit's screens come oldest first, and it says so.
4. Rows under a refused table vanished silently: each now has a refusal.
5. `data-part='7'`, `data-part=7` and upper case slipped past the strip: one regex for all.
6. A temporary script failed typecheck: fixed, now `scripts/remake-plant.ts`.
7. `spec/behavior.md` missed the fact redraw: added, with *pasted on* and the oldest-first order.
8. *Left*: *remove it* comes before *leave alone what the user wrote*; code refuses those lines.
9. `fixer-wording.ts` reads a file in git-ignored `temp/`: its header says where it comes from.
